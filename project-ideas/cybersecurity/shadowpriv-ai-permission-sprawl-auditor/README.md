# 🛡️ ShadowPriv AI: Intelligent SaaS-to-SaaS Permission Sprawl & Over-Privilege Auditor

## Category / Domain
Cybersecurity / Cloud Governance

## Date
2026-10-28

## Short Description
ShadowPriv AI is a governance platform that automatically discovers, audits, and remediates "permission sprawl" across an organization's SaaS ecosystem (Google Workspace, GitHub, Slack, Salesforce, etc.), identifying third-party apps with excessive OAuth scopes or dormant high-privilege access.

## Problem Statement
Modern organizations use hundreds of SaaS tools that integrate with one another via OAuth. Often, a simple browser extension or a productivity bot asks for "Read/Write access to all files" or "Admin access to the repository." Once granted, these permissions are rarely reviewed. This creates a massive "Shadow SaaS" attack surface where a single compromised third-party app can lead to a supply-chain breach of the entire corporate data suite. IT teams lack visibility into which apps have which permissions and whether those permissions are actually being used.

## Proposed Solution
ShadowPriv AI connects to major SaaS platforms via administrative APIs to index every third-party integration and OAuth grant. It uses AI to analyze the delta between "Requested Scopes" and "Actual Usage" (via audit logs). If an app has "Delete" permissions but has only ever "Read" data for 90 days, the AI flags it for a downgrade. It also uses NLP to compare the app's stated purpose (from its website/manifest) with its technical permissions to find suspicious mismatches.

## Core Features
- **Multi-SaaS Discovery:** Centralized inventory of all third-party apps connected to Google, GitHub, Slack, Microsoft 365, and Salesforce.
- **Scope Mapping:** Visual breakdown of permissions (e.g., PII access, administrative, data deletion) for every connected app.
- **Dormant Access Detection:** Identification of integrations that haven't exchanged tokens or called APIs in a configurable period (e.g., 30/60/90 days).
- **Risk Scoring:** A proprietary score for each app based on scope sensitivity, vendor reputation, and data access volume.
- **Automated Remediation:** One-click revocation of OAuth tokens or automated email workflows to app owners asking for justification.

## Advanced Features
- **Usage-Based Least Privilege:** AI-driven recommendations to downgrade scopes based on historical API activity logs.
- **Policy-as-Code Integration:** Define global policies (e.g., "No app outside the Finance department can have access to Stripe") and auto-revoke violators.
- **Vendor Manifest Auditor:** AI parses the third-party vendor's privacy policy and terms of service to ensure they don't claim ownership of data accessed via OAuth.
- **Shadow-IT Correlation:** Cross-references OAuth grants with corporate spend (via finance integrations) to find "free" apps that are high-risk.

## AI/ML Integration
- **NLP for Intent Alignment:** Uses an LLM to read the "App Description" and "Requested Scopes" to detect "Intent-Permission Mismatch" (e.g., a Calculator app asking for "Read Emails").
- **Anomaly Detection:** Identifies sudden spikes in API activity from a third-party app that might indicate data exfiltration.
- **Risk Classification:** Clustering algorithms to categorize apps into risk buckets based on historical breach data of similar vendors.

## Suggested Tech Stack
- **Backend:** Python (FastAPI) for high-performance API handling and integration logic.
- **Frontend:** React with Tailwind CSS and D3.js for complex permission relationship graphing.
- **Database:** PostgreSQL (Metadata) and Neo4j (Graph database to map the web of app-to-data relationships).
- **Task Queue:** Celery with Redis for periodic scanning of SaaS audit logs.
- **AI Framework:** LangChain with OpenAI GPT-4o for document/policy analysis.

## Database Design
- `Organizations`: Stores tenant-level settings and SaaS provider credentials (encrypted).
- `SaaS_Providers`: Definitions for Google, GitHub, etc., and their specific scope hierarchies.
- `Integrations`: Individual OAuth grants, including `client_id`, `scopes_granted`, and `last_used_at`.
- `Audit_Logs`: Cached records of API calls made by third-party apps to determine actual usage.
- `Risk_Alerts`: Findings generated by the AI engine requiring human review.

## API Route Ideas
- `GET /api/v1/inventory`: List all discovered apps across all connected SaaS platforms.
- `GET /api/v1/apps/{app_id}/risk-profile`: Detailed risk breakdown and AI-generated justification.
- `POST /api/v1/remediate/revoke`: Revoke an OAuth grant via the provider's API.
- `POST /api/v1/policy/check`: Manually trigger a policy compliance scan.

## UI Pages
- **Global Security Dashboard:** High-level overview of "Total Apps," "High Risk Apps," and "Data Exposure Surface."
- **App Inventory Explorer:** Filterable list of apps with "Drill-down" views into specific permission scopes.
- **Permission Graph:** A node-link diagram showing which apps have access to which sensitive data folders or repositories.
- **Policy Manager:** Interface to write and test "Least Privilege" rules.

## MVP Plan
1. Implement OAuth integration for one major provider (e.g., GitHub or Google Workspace).
2. Create a basic scanner that lists all third-party apps and their scopes.
3. Build the risk scoring engine based on a static list of "Sensitive Scopes."
4. Develop the dashboard to display the inventory and highlight high-risk apps.
5. Implement a "Revoke" button that calls the provider's API.

## Future Scope
- **Browser Extension:** A companion extension to block users from granting high-risk permissions in real-time.
- **SIEM/SOAR Export:** Push risk alerts to Splunk, Sentinel, or Panther.
- **Auto-Quarantine:** Move suspicious apps into a restricted "sandbox" scope automatically upon detection of anomalous behavior.
