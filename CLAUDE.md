# GainTheBrain Claude Instructions

## Goal

Maintain a Next.js + TypeScript + React website that lets the owner browse, search, read, summarize, and ask questions about all project ideas generated by the daily agent.

## Architecture

- The website is a Next.js app in the repository root.
- Project ideas are Markdown files. The app reads them from:
  - `project-ideas/<category>/<project-slug>/README.md`
  - `ai-builders-congress/<domain>/<project-slug>/README.md`
- The main reader loads idea data server-side through `lib/ideas.ts`.
- `/api/ideas` returns the current Markdown catalog as JSON.
- `/api/ideas/ask` calls the configured AI provider from the server only.

## Security Rules

- Never expose private API keys in browser code.
- Never create `NEXT_PUBLIC_AI_API_KEY`, `NEXT_PUBLIC_OPENROUTER_API_KEY`, or any other public secret.
- Keep provider credentials in server environment variables only:
  - `AI_API_KEY`
  - `AI_API_URL`
  - `AI_MODEL`
- Client components may call only internal routes such as `/api/ideas/ask`.
- Do not use `dangerouslySetInnerHTML` for project Markdown. Render Markdown as React text nodes or sanitize it first.
- Keep `.env` untracked. Update `.env.example` with names only, never real values.

## Daily Agent Plan

1. Generate exactly one unique project idea per successful daily run.
2. Save it as a `README.md` file in the correct folder under `project-ideas` or `ai-builders-congress`.
3. Use the required README headings from `scripts/daily_project_agent.py`.
4. Do not build or commit generated website bundles.
5. Commit only the new Markdown idea file.
6. Let the Next.js website read the Markdown at request time in development and at build/request time in deployment.

## Website Work Plan

1. Keep the first screen as the actual reader app, not a marketing landing page.
2. Preserve the core workflows:
   - Search ideas.
   - Filter by collection.
   - Filter by folder/domain.
   - Select an idea.
   - Read structured sections.
   - Ask the server-side AI assistant about the selected idea.
3. Keep UI states useful:
   - Empty search results.
   - Missing AI configuration.
   - Loading assistant answer.
   - AI provider errors with secrets redacted.
4. Keep cards and panels compact enough for repeated reading.
5. Make responsive layouts work on mobile and desktop.

## Development Commands

```bash
npm install
npm run dev
npm run typecheck
npm run build
python -m unittest tests.test_daily_project_agent
```

On Windows PowerShell, use `npm.cmd` if `npm` is blocked by execution policy:

```powershell
npm.cmd install
npm.cmd run dev
npm.cmd run typecheck
npm.cmd run build
```

## Deployment Notes

- Set `AI_API_KEY`, `AI_API_URL`, and `AI_MODEL` in the hosting provider's server environment.
- Do not set provider keys as public frontend variables.
- Configure the host to rebuild after daily agent pushes, or run the app dynamically so it reads new Markdown from the filesystem.
- If the AI assistant will be public, add authentication or rate limiting before production launch.
